# NEO Bank — UI/UX Design — Brand

_Part of [07-ui-ux-design.md](../../07-ui-ux-design.md)._

## Purpose

Defines the NEO Bank brand marks, their colours, and the rules for using them. The marks are original to this project and must not be derived from any existing institution ([00-overview.md](../../00-overview.md)). Like the rest of the design system, the brand is expressed with the tokens in [`design-tokens.md`](../system/design-tokens.md).

## 1. Assets

Every mark ships in a **light** and a **dark** variant so it reads correctly on either theme. The SVG files are the **source of truth**; the PNG files are generated from them — never edit a PNG by hand.

Assets are named `<subject>-<theme>`:

- **subject** — `mark` (the symbol alone) or `text` (the horizontal lockup: mark + `NEO` wordmark).
- **theme** — `light` (for light backgrounds) or `dark` (for dark backgrounds).

| File                           | Format   | Purpose                                                                |
| ------------------------------ | -------- | ---------------------------------------------------------------------- |
| `svg/logo-mark-light.svg`      | SVG      | Mark for light backgrounds — favicon, app icon, avatar, tight spaces.  |
| `svg/logo-mark-dark.svg`       | SVG      | Mark for dark backgrounds.                                             |
| `svg/logo-text-light.svg`      | SVG      | Horizontal lockup for light backgrounds — mark plus `NEO` wordmark.    |
| `svg/logo-text-dark.svg`       | SVG      | Horizontal lockup for dark backgrounds.                                |
| `images/logo-mark-light.png`   | PNG      | Raster of the light mark (generated by `brand.sh`).                    |
| `images/logo-mark-dark.png`    | PNG      | Raster of the dark mark (generated by `brand.sh`).                     |
| `images/logo-text-light.png`   | PNG      | Raster of the light lockup (generated by `brand.sh`).                  |
| `images/logo-text-dark.png`    | PNG      | Raster of the dark lockup (generated by `brand.sh`).                   |
| `brand.sh`                     | Bash     | Rasterises every `svg/*.svg` to `images/*.png`.                        |
| `README.md`                    | Markdown | This document.                                                         |

Pick the variant that matches the surface the logo sits on — use the `light` asset on light surfaces and the `dark` asset on dark surfaces. Where the surface theme is switchable (for example the application header), swap the asset with the theme.

## 2. The mark

A single, flat shape: a **vertical hexagon with rounded corners**. "Vertical" means a regular hexagon rotated so a vertex points up and down (and the left and right edges are vertical); it is taller than it is wide. Every corner is rounded with a radius of roughly a quarter of the mark's height, giving a soft, modern, "chip"-like silhouette.

The mark is drawn in a `256 × 256` viewBox and is inset so it has even padding on all four sides.

## 3. The lockup

`logo-text-<theme>.svg` places the mark on the left and the wordmark `NEO` immediately to its right, vertically centred on the mark. The wordmark is set in **uppercase** so it reads as an acronym, not a word. The asset is padded evenly on the left and right so it stays optically centred wherever it is placed.

Use the lockup in the application header and marketing headers; use the mark alone where horizontal space is scarce. See the layout rules in [`layout.md`](../system/layout.md).

## 4. Colour

The mark carries the brand colour; the wordmark carries the theme's primary text colour, so the two elements never compete. The marks use flat colour only — no gradients, no second accent.

### Mark

| Theme          | Token               | Value     |
| -------------- | ------------------- | --------- |
| Light surfaces | `color-primary`     | `#2563EB` |
| Dark surfaces  | `color-primary` (dark) | `#3B82F6` |

### Wordmark

| Theme          | Token                   | Value     |
| -------------- | ----------------------- | --------- |
| Light surfaces | `color-text-primary`    | `#111827` |
| Dark surfaces  | `color-text-primary` (dark) | `#F9FAFB` |

For a monochrome or on-image treatment, use `color-primary-content` (`#FFFFFF`) — or its inverse `#0B1220` on light photography — for both elements.

Rules:

1. Use only the colours above. Do not introduce colours outside the design tokens.
2. **The wordmark is never the primary colour.** It is always `color-text-primary`, which is dark on light surfaces and light on dark surfaces.
3. Pair the mark and wordmark with the correct surface: the `light` asset on light surfaces, the `dark` asset on dark surfaces.
4. Never place the logo on a background that does not meet the contrast requirements in [`accessibility.md`](../system/accessibility.md).

## 5. Typography

- **Typeface:** Inter (the product typeface). Serve or install it; the SVG declares `Inter` with a system sans-serif fallback.
- **Weight:** Bold (`font-weight: 700`).
- **Case:** Uppercase.
- **Tracking:** Tight (`letter-spacing: -0.015em`).
- **Colour:** `color-text-primary` for the theme — dark on light surfaces, light on dark surfaces.
- **Optical size:** the wordmark cap height is roughly half the mark height so the two elements look balanced.

The wordmark is **live text** in the SVG, which keeps it editable. Before using the lockup in a context that must be pixel-identical everywhere (favicon, social card, print, third-party use), outline the text to paths in a vector editor — see [Production notes](#9-production-notes).

## 6. Clear space and minimum size

- **Clear space:** keep a margin of at least **half the mark's height** clear on every side of the lockup (and the mark). Nothing else — text, rules, other logos — may enter that space.
- **Minimum size:** the mark is legible down to **24 × 24 px** (digital) or **8 mm** (print); the lockup down to **96 px** wide (digital) or **32 mm** (print). Below these, use the mark alone.

The application header uses the mark at 24 px (`h-6 w-6`), matching the [prototypes](../prototypes/README.md).

## 7. Usage

Do:

1. Scale proportionally; keep the aspect ratio.
2. Use the supplied SVG (or a PNG generated from it) as-is.
3. Keep the clear space and minimum sizes above.
4. Use the `light` and `dark` variants for the surface the logo sits on.
5. Keep the wordmark in `color-text-primary` for the theme.

Do not:

1. Recolour with anything other than the tokens above.
2. Paint the wordmark in the primary colour (or any colour other than `color-text-primary`).
3. Stretch, squash, rotate, skew, or outline the mark.
4. Add gradients, drop shadows, glows, or strokes.
5. Rearrange the lockup (for example, put the wordmark above the mark) or retypeset the wordmark in another font, weight, or case.
6. Place the logo on a busy, low-contrast, or clashing background.

### Accessibility

- When the logo appears next to visible `NEO` text (for example the lockup), it is decorative: mark it `aria-hidden="true"`.
- When the mark is used alone as a link or an icon, give it an accessible name and keep its `<title>`.
- The `NEO` text in the lockup is text, so it inherits the text-contrast rules in [`accessibility.md`](../system/accessibility.md).

## 8. Generating images

Run the script to regenerate every PNG from the SVGs:

```sh
./docs/07-ui-ux-design/brand/brand.sh        # 1024px wide (default)
./docs/07-ui-ux-design/brand/brand.sh 512    # 512px wide
```

The script picks the first available rasteriser — `rsvg-convert`, `inkscape`, `cairosvg`, or ImageMagick — and writes `images/<name>.png` for each `svg/<name>.svg`. Commit the SVG and PNG changes together.

## 9. Production notes

- The lockup's wordmark is live text. Rendering depends on the `Inter` font being installed; without it the rasteriser falls back to a system sans-serif and the PNG may differ slightly between machines. For brand-accurate, deterministic assets, install Inter, or convert the wordmark to paths.
- When the frontend is scaffolded, copy the runtime-ready assets into the app's `public/` directory (for example `logo-mark-light.svg`, `logo-text-light.svg`, `favicon.ico`, `og-image.png`) and keep these files as the design source.
