# NEO Bank — Test Documentation

## Purpose

Defines how test cases, test reports, and test evidence are documented across all test layers.

## 1. Test Cases

Critical test cases are documented with the following fields:

| Field | Description | Example |
|-------|-------------|---------|
| Test ID | Unique identifier | `FIN-001`, `SEC-003` |
| Description | What the test verifies | "Transfer with insufficient funds is rejected" |
| Preconditions | Setup required | "Account with 1000 cents balance exists" |
| Steps | Actions performed | "Initiate transfer of 5000 cents" |
| Expected result | Expected outcome | "Transfer status = failed, balance unchanged" |
| Actual result | Observed outcome (if failed) | Filled in on failure |
| Status | Pass/Fail/Skip | `pass` |
| Related requirement | FR/NFR reference | `FR-032`, `NFR-020` |

### Test Case Template

```markdown
## Test Case: FIN-001

**Description:** Transfer with sufficient funds completes successfully.

**Preconditions:**
- Source account `acc-test-1` has balance 10000 cents
- Destination account `acc-test-2` exists
- User is authenticated

**Steps:**
1. Initiate transfer of 5000 cents from `acc-test-1` to `acc-test-2`
2. Wait for transfer status to reach terminal state
3. Query source account balance
4. Query destination account balance

**Expected Result:**
- Transfer status: `completed`
- Source balance: 5000 cents
- Destination balance: increased by 5000 cents
- Transaction records exist for both debit and credit

**Related Requirements:** FR-032, FR-039, NFR-020, NFR-021
```

## 2. Test Reports

Test reports are generated and published as CI artifacts:

### Coverage Reports

- Format: HTML + text + LCOV
- Generated by: `go test -cover` (backend), Vitest (frontend)
- Published to: Codecov/Coveralls
- Retention: 30 days

### Test Results

- Format: JUnit XML
- Generated by: `go test -json`, Playwright reporter
- Published to: CI artifacts
- Retention: 30 days

### Flaky Test Alerts

- Detected by: CI test history analysis
- Alert destination: Team channel (Slack/email)
- Contents: Test name, failure count, flakiness rate

### Performance Regression Alerts

- Detected by: Test duration trend analysis
- Threshold: > 20% increase from baseline
- Alert destination: Team channel

## 3. Test Evidence

For critical scenarios (FIN, SEC, EVT), test evidence is captured:

- **Cassandra queries** — CQL statements and results for balance verification.
- **Kafka events** — Event payloads published and consumed.
- **API requests/responses** — HTTP status codes, headers, bodies.
- **Console output** — Test logs with correlation IDs.

Evidence is attached to failed test reports for diagnosis.

## 4. Documentation Standards

- Test cases are version-controlled alongside test code.
- Test IDs match requirement IDs (FR/NFR) for traceability.
- Test reports are generated automatically in CI (no manual documentation).
- Test evidence is captured automatically (no manual screenshots/logs).
- Documentation is updated when test scenarios change.
