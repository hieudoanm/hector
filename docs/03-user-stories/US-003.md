# US-003: Log out and invalidate session

## User Story
**As a** authenticated user,
**I want to** log out and invalidate my session,
**so that** my account remains secure.

## Acceptance Criteria
- Given an active session, when I log out, then the refresh token is invalidated and can no longer be used.
- Given a logged-out session, when I attempt to access protected endpoints with the access token, then the system rejects the request once the token expires.
- Logging out does not require invalidating the short-lived access token immediately (it will expire naturally).

## Technical Implementation Details

### API Endpoint
- **Method**: POST
- **Path**: `/api/v1/logout`
- **Headers**: 
  - Content-Type: application/json
  - Authorization: Bearer <accessToken>
- **Request Body**:
  ```json
  {
    "refreshToken": "string (opaque refresh token, 7 day expiry)"
  }
  ```
- **Success Response (204 No Content)**
- **Error Responses** (error envelope `{"error":{"code","message","details","requestId"}}`):
  - 401 UNAUTHENTICATED: Missing or invalid access token
  - 401 INVALID_REFRESH_TOKEN: Missing, invalid, expired or already revoked refresh token

### Database Schema Changes
**Auth Service Keyspace** (builds on US-001 and US-002):
- Table: `refresh_tokens` 
  - Additional column: 
    - `revoked` (boolean, default false) - tracks if token has been logged out

### Security Considerations
- Refresh token invalidation: Mark as revoked in database rather than deleting (for audit trail)
- Access tokens are short-lived (15 minutes) and will expire naturally; no immediate invalidation needed on logout
- Refresh token must be validated (not expired, not already used/revoked) before revocation
- Logout endpoint requires valid access token for authentication (to prevent unauthorized logout attempts)
- Implement refresh token rotation on logout for added security (generate new token, revoke old one)
- Protect against token theft: Even if refresh token is stolen, it becomes useless after legitimate logout

### Error Handling
- Missing or invalid refresh token: Return 401 with error code `INVALID_REFRESH_TOKEN` and message "Invalid refresh token"
- Expired refresh token: Return 401 with error code `INVALID_REFRESH_TOKEN` and message "Invalid refresh token"
- Already revoked refresh token: Return 401 with error code `INVALID_REFRESH_TOKEN` and message "Invalid refresh token"
- Missing access token in Authorization header: Return 401 with error code `UNAUTHENTICATED` and message "Missing or invalid access token"
- Expired access token in Authorization header: Return 401 with error code `TOKEN_EXPIRED` and message "Access token expired"
- Internal server errors: Return 500 with error code `INTERNAL_ERROR`

### Test Cases
1. Valid logout with correct refresh token → 204 No Content, refresh token marked revoked
2. Logout with invalid refresh token → 401 `INVALID_REFRESH_TOKEN`
3. Logout with expired refresh token → 401 `INVALID_REFRESH_TOKEN`
4. Logout with already used/revoked refresh token → 401 `INVALID_REFRESH_TOKEN`
5. Logout without Authorization header → 401 `UNAUTHENTICATED`
6. Attempt to use revoked refresh token for new access token → 401 `INVALID_REFRESH_TOKEN`
7. Access protected endpoint with valid access token after logout → 200 OK (token still valid until expiry)
8. Access protected endpoint with expired access token after logout → 401 `TOKEN_EXPIRED`
9. Concurrent logout requests with same refresh token → First succeeds, others get 401 `INVALID_REFRESH_TOKEN`
10. Verify refresh token is marked revoked (not deleted) in database
11. Verify access token still works until natural expiration after logout
