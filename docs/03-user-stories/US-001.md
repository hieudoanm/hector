# US-001: Register a new account

## User Story

**As a** new user,
**I want to** register a bank account with email and password,
**so that** I can start using the banking platform.

## Acceptance Criteria

- Given a valid email and strong password, when I register, then an account is created with a unique account ID (UUID v7) and a configurable initial balance (`INITIAL_BALANCE_CENTS`, `0` by default; see [`00-overview.md`](../00-overview.md)).
- Given an email that is already registered, when I attempt to register, then the system rejects the request with `409 EMAIL_ALREADY_REGISTERED` (registration is the only flow that confirms email uniqueness; login and other endpoints never reveal whether an email exists).
- Given a weak password, when I register, then the system rejects the request with clear password-strength requirements.
- Given a successful registration, when I complete the flow, then I receive an account ID, a user ID, an access token (15 min expiry) and a refresh token (7 day expiry).
- Given a registration attempt with an invalid email format, when I submit, then the system rejects the request with a clear error.
- Passwords are hashed using Argon2id before storage.

## Technical Implementation Details

### API Endpoint

- **Method**: POST
- **Path**: `/api/v1/register`
- **Headers**:
  - Content-Type: application/json
- **Request Body**:
  
  ```json
  {
    "email": "string (valid email format)",
    "password": "string (min 12 chars, mixed case, number, symbol)"
  }
  ```

- **Success Response (201 Created)**:

  ```json
  {
    "accountId": "uuid (UUID v7)",
    "userId": "uuid (UUID v7)",
    "accessToken": "string (JWT RS256, 15 min expiry)",
    "refreshToken": "string (opaque, 7 day expiry)",
    "tokenType": "Bearer",
    "expiresIn": 900
  }
  ```

- **Error Responses** (error envelope `{"error":{"code","message","details","requestId"}}`):
  - 400 VALIDATION_ERROR: Invalid email format or weak password
  - 409 EMAIL_ALREADY_REGISTERED: Email already registered
  - 429 RATE_LIMITED: Auth rate limit exceeded (100 req/min/IP)

### Database Schema Changes

**Auth Service Keyspace**

- Table: `users`
  - Columns:
    - `user_id` (UUID v7, primary key)
    - `email` (text, unique)
    - `password_hash` (text, Argon2id hash)
    - `created_at` (timestamp)
    - `updated_at` (timestamp)
- Table: `refresh_tokens`
  - Columns:
    - `token_id` (UUID v7, primary key)
    - `user_id` (UUID v7, foreign key to users)
    - `token_hash` (text, SHA-256 hash of the opaque refresh token; the raw token is never stored — never bcrypt, never JWT)
    - `expires_at` (timestamp, 7 days after issue)
    - `created_at` (timestamp)
    - `revoked` (boolean, default false)

### Security Considerations

- Passwords must be hashed using Argon2id with appropriate parameters (memory=64MB, iterations=3, parallelism=4)
- Email validation should follow RFC 5322 standard
- Rate limiting: 100 requests/minute per IP address for auth endpoints (`/api/v1/register`, `/api/v1/login`, `/api/v1/refresh`, `/api/v1/logout`). This request-volume limit is independent of the failed-login lockout (5 failed logins per 15 minutes) described in US-002; whichever limit is reached first applies and returns 429 `RATE_LIMITED` with a `Retry-After` header
- Refresh tokens are opaque random strings with a 7-day expiry, stored only as SHA-256 hashes; access tokens are JWTs (RS256, 15 minutes)
- No account enumeration outside registration: invalid input returns a generic 400 `VALIDATION_ERROR`; the only email-existence signal in the system is the canonical 409 `EMAIL_ALREADY_REGISTERED` on this endpoint. Login (US-002) and every other endpoint never reveal whether an email exists
- Password strength requirements:
  - Minimum 12 characters
  - At least one uppercase letter
  - At least one lowercase letter
  - At least one digit
  - At least one special character
  - Maximum 128 characters

### Error Handling

- Invalid email format: Return 400 with error code `VALIDATION_ERROR` and message "Invalid email format"
- Weak password: Return 400 with error code `VALIDATION_ERROR` and message "Password must be at least 12 characters and contain uppercase, lowercase, number, and symbol"
- Email already registered: Return 409 with error code `EMAIL_ALREADY_REGISTERED` and message "Email already registered"
- Rate limit exceeded: Return 429 with error code `RATE_LIMITED` and message "Too many requests" plus a `Retry-After` header
- Internal server errors: Return 500 with error code `INTERNAL_ERROR`

### Test Cases

1. Valid registration with strong password → 201 Created with account ID and tokens
2. Registration with invalid email → 400 Bad Request
3. Registration with weak password → 400 Bad Request
4. Registration with existing email → 409 Conflict
5. Missing email or password in request → 400 Bad Request
6. Password with exactly 12 characters meeting all requirements → 201 Created
7. Password with 128 characters meeting all requirements → 201 Created
8. Password with 129 characters → 400 Bad Request
9. Concurrent registration attempts with same email → Only one succeeds, others get 409
10. Verify password is hashed (not stored in plain text) in database
